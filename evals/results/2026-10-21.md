## Fewer human sign-offs (runs 8-9, all 6 tasks, k=3)

Across runs 2-4, 25 of 30 trials stopped for a `verify:"human"` sign-off. About half of those criteria were redundant: "the test file is
unchanged" (the engine already enforces that), and "the title is unchanged" or "README shows `echo hi | node bin/count.js`" (grep can check
those). The drafter is now told to prefer checks, with grep suggested only when grep is allowed. Run 8's first wording suggested grep under
node-library, which has no grep, so one draft failed. Run 9, with the fix:

|---|---|---|---|
| readme-usage | 3/3 | 11452 | 27 |

| **all** | **17/18 (94%)** | 23602 | 47.5 |

Human sign-offs: **8 of 18** trials (was 25 of 30).

**The count-cli failure, diagnosed (kept with `--keep`).** The acceptance task wrote `count('one\ttwo  three')` → `chars: 15`, but the
string has 14 characters. Acceptance tests are read-only for the implementer, so no retry could pass. The haiku, sonnet and opus attempts each
reported the wrong expectation and left it alone. Opus wrote: "I didn't add a special case or an off-by-one to force a pass". The anti-cheat
design held, but the goal only said "failed after 3 attempt(s)". The block reason now names the acceptance task and file, and the report keeps
the worker's note. Earlier count-cli and changelog failures (runs 3 and 6) were probably the same kind of thing, but that's unverified.

## Totals

All valid real trials today (runs 2-9): **78 of 84 passed**. Of the 6 failures: 2 were the grep bug (fixed), 1 was the grep-advice regression in run 8 (fixed), 1 was a wrong acceptance test (diagnosed above; now reported clearly), and 2 are unexplained (1 changelog in run 3, 1 count-cli in run 6).

## History and what each run found

- **Run 1: invalid** (`2026-10-21-run1-invalid.*`). 10/12 trials timed out: drafts add `verify:"human"` criteria (for example
  "the title is unchanged") and `run` stayed attached waiting for a human `confirm`. Fix: the harness runs with `--no-wait` and,
  only when its own grader passes, stands in for the human and `confirm`s (recorded as `human_confirm`). 25 of the 30 valid trials
  stopped for at least one human sign-off: in real use that is a human step on most small goals.
- **Run 2** (`2026-10-21-run2.json`): 10/12. Both failures were changelog-entry: the drafter wrote the check
  `grep -qx "- add retry to the fetcher" CHANGELOG.md`; grep reads a pattern starting with `-` as an option, so the check can never pass.
  Fix (orchestrator): the draft and plan validators refuse such argv with the `-e` fix, and the draft prompt warns about it.
- **Run 3** (`2026-10-21-run3.json`): 11/12, above. **Run 4** (`2026-10-21-run4-changelog.json`): changelog-entry 6/6.

Plans with commands (the node-library tasks) always needed a human plan approval (`plan_needed_approval`), by design.
