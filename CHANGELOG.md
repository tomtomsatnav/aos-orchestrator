# Changelog

## Unreleased
- Demo UX: the draft display renders a criterion's lines separately instead of a literal `\u000a`; drafted goals get small default budgets (150000 tokens, 1200 s, 2 attempts, never above the rules) described truthfully (draft default / proposed by the model / your flag, with the rules' limit) and the rules summary shows the compiled limits; `aos-orch draft --max-tokens N --max-wall-s N --tier T` only tighten (validated before any model call). New read-only `aos-orch plan <goal>`; `run` prints the exact next command when it stops for plan approval or human confirmation; `run --wait-approval` stays attached and continues only after the human's `approve-plan` / `confirm` command. The rules summary lists a profile's own check-allowlist additions in a separate block from real loosenings. Plan review and the server plan view flag tasks whose `path_scope` is not mentioned in the goal text (`beyond_prompt`, `beyond_paths`; informational). The planner prompt discourages verification-only tasks. `rules check <goal.json> --layer goal` checks the goal file's `orch.rules`.
- Verification fixes: control, bidi and invisible characters are escaped in all worker-controlled text a human reads (control-server goal/approval/plan/event views, CLI `approvals`, `goals`, `status` JSON and text); the control-character set now also covers soft hyphen, U+034F, Hangul fillers, U+180E, U+2061-2064, U+206A-206F, interlinear annotation marks and lone surrogates. New plans bind the task title, description, output contract and acceptance into the tasks hash (`tasks_hash_v: 2`; plans approved earlier keep v1) and the plan review shows them. Glob complexity is bounded (variants x tokens <= 2048, `path_scope` <= 512 characters) and `scopeHitsDeny` has a work budget that answers "overlap" when exhausted.
- Prompt to goal (rules R12): `aos-orch draft "<prompt>" --repo <path>` and `POST /api/goals/draft` make one no-tools model call and return a validated draft (check argv only from the compiled check allowlist, budgets no higher than the rules, no rule or trust fields, control characters rejected, >= 2 criteria or a human-review one); nothing is created until the human submits. Vague prompts return questions. New criterion kind `verify: "human"`: the goal stays `blocked` ("awaiting human confirmation") until `aos-orch confirm <goal> <criterion>` or `POST /api/goals/:id/criteria/:cid/confirm`. `POST /api/goals` criteria may carry a `check` (it must already be allowed by the rules or the request's `check_allowlist`) or `verify`. Profiles `node-library` and `docs-only` for drafts.
- Rules R10: `aos-orch rules show [goal]`, `rules check <file> [--layer]` and `rules explain <goal> <task> '<tool json>'` (a pure dry run of the policy evaluate: decision, reason and rule id; writes nothing, creates no approval).
- Rules R9: `approval_policy.outside_allowlist: "deny"` now maps onto `worker.bash.ask_on` (unknown commands are denied, not asked); `approval_policy.dangerous`, unknown `approval_policy` keys, `policy.paths.write` and `policy.approval.on_timeout` are reported once in an `orch.rules.deprecated` event and otherwise ignored. Old goals still load.
- Rules R8: the retry ladder, `retry.same_tier_retries`, `retry.no_escalate`, `retry.uncertain_limit_max`, `budgets.soft_frac`, `budgets.hard_grace_s`, `parallel.soft_budget_blocks_tier`, `plan.planner_tier` and `plan.planner_timeout_s` now come from the compiled rules (defaults reproduce the old constants). The governor thresholds come from the user layer only (a goal's `orch.governor` is ignored; legacy goals keep it). Engine events `task.retried`, `task.failed` (final), `budget.exceeded`, `orch.governor.paused`, `orch.integrate.conflict` and `orch.plan.approval_required` carry `data.rule`.
- Opt-in macOS OS sandbox for worker `claude` processes: `aos-orch run goal.json --sandbox-workers` / `orch.sandbox_workers`. Limits writes (worktree, goal tmp, approvals, its own session-env and scratchpad); network and keychain reads stay open. Default unchanged. Guards against accidents; not a boundary against a determined malicious worker.
- Worker sandbox no longer allows writes to `~/.claude/shell-snapshots`, `~/.claude.json`, other sessions' `~/.claude/session-env/<id>` and `/tmp/claude-<uid>/` scratchpads, or the engine's `$TMPDIR`.
- Lock fix: `serve` no longer holds a goal's lock without ticking it; `run` against a locked goal exits 5; `lockStatus` treats a lock older than its ttl as dead (no WEDGED message naming a reused pid).
- Rate-limit matcher keyed on real captured error shapes; text fallback now applies only to API-error-shaped results (never worker-authored result text or `errors[]`); after 2 consecutive uncertain matches for a task the attempt counts; a real limit during a shorter overload pause extends the pause (longer wins); a manual pause is never replaced by a timed one.

## 0.1.0 (experimental)
- Engine that plans a Goal into tasks and dispatches headless Claude Code workers in git worktrees; policy hook, path scopes, budgets, control server and supervisor.
- Status: experimental. Exercised by 8 small real runs, 7 achieved and 1 blocked by a test-setup error (one with a real Opus planner; all tasks solved at the Haiku tier except one run that ladder-escalated through an environment failure); everything else is tested against a scripted fake `claude`. Rate-limit handling has never met a real limit.
