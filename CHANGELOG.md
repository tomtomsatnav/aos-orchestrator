# Changelog

## Unreleased
- Guard mode: verify any agent's work without orchestration. `aos-orch verify --repo <path> [--base main] [--check "..."]... [--tree <commit>] [--json]` (`lib/guard.mjs` `verifyTree`) copies the finished tree into a private scratch repo (bounded; the agent's `.git` config and hooks are never used to run anything) and applies the engine's own guardrails against the base commit: `analyzeDiff` (deleted / skipped / weakened tests, config and harness tamper), the checks via the sandboxed `runChecks` path judged against base-commit baselines (`judgeRun`, `judgePerFile`), the tree must not change while they run, and the ORIGINAL test files re-run over the tree. A modified existing test whose original version then fails is `tests_edited`. Fails closed without an OS sandbox (`--unsandboxed-checks` opts out). Exit 0 accepted, 1 rejected. Evals: new arms `guarded` (one bare `claude -p` session, then the guard; a rejected tree is graded as the untouched seed) and `guarded-cascade` (haiku, then sonnet, then opus in the same tree on capability failures only, with the guard's report fenced as untrusted; an integrity failure stops at once). `_readTestFiles` moved to `anticheat.mjs` `readTestFiles` (shared, unchanged).
- When an implementation task fails on a test written by an acceptance task (read-only for it, so no retry can fix a WRONG test), the block reason names the acceptance task and file and says to fix the test by hand or re-plan; the worker's last note is kept (`last_failure.worker_note`, control characters escaped) and shown in the report as untrusted. Found by the real evals: an acceptance test expected 15 characters for a 14-character string, and the haiku, sonnet and opus workers each diagnosed it correctly and refused to special-case the answer.
- The drafter is told to prefer checks over `verify:"human"` (grep for literal lines, only when grep is allowed) and not to add an "existing tests unchanged" criterion (the engine enforces it). Real evals: trials that stopped for a human sign-off fell from 25/30 to 8/18 at the same pass rate.
- Fix (found by the real evals): a `grep`/`rg` check whose pattern starts with `-` (for example a markdown bullet) is read as an option and fails on every run. The draft and plan validators now refuse it with the `-e` fix, the draft prompt warns about it, and a hand-written goal criterion gets a plan-approval warning. Evals harness: `--no-wait`, grader-gated stand-in `confirm` for `verify:"human"` criteria, usage recorded on timeout.
- Test-integrity coverage, round 2 (`test/redteam2.test.mjs`, fake-claude end to end): the preload now records and fails (`harness_tamper`) a module loader hook registration, a replaced fs read function, and an unobserved `node` child process (`spawnSync` result never read, async child never waited for); the verdict's test counts come from the engine's reporter channel instead of stdout (`summaryOfRun`); baselines (total and protected per-file) are recorded twice and the larger count is enforced (`mergeBaselineRuns`, `baseline_unstable` warning). Held already and now pinned by tests: spoofed TAP/summary lines, padding with trivial new files, self-check results never used by the verdict, loader flags in config files. Known limits and honest false positives are listed in the README. Cost: the baseline phase runs each check twice.
- Security review of worker self-check (`test/selfcheck-hardening.test.mjs`): (S1) the inbox is read with `O_NOFOLLOW|O_NONBLOCK`, regular files of at most 4 KB only (FIFO / symlink-to-`/dev/zero` hangs and multi-GB reads are gone). (S2) at most 64 names scanned per tick, invalid entries bulk-deleted, an attempt that files more than `self_checks_max + 16` bad requests is no longer serviced (`orch.check.self_flooded`); responses move to an engine-owned dir the worker sandbox can read but not write, so a swapped inbox cannot redirect engine writes. (S3) self-check timeout capped at `min(check, stall_after_s - 30, wall clock left)`, counts as activity for the stall detector, is killed and awaited before collection, and the worktree must be unchanged after the authoritative checks (`worktree_mutated_during_checks`). (S4) `run goal.json` on an existing goal reports the stored `sandbox_workers`; security.md default-on text fixed. (N2) developer-dir allowance only for real developer dirs, from the engine's env. (N3) stale responses and `selfcheck-<task>` tmp dirs removed between attempts.
- Anti-cheat hardening (red team B1-B3, `test/redteam.test.mjs`): (B1) every engine-run `node --test` check runs with an engine-owned preload (`lib/harness-preload.mjs`, copied read-only outside the worktree) that freezes and verifies `node:assert` / `node:assert/strict` / `node:test`, with nonce-carrying exit markers; missing, forged or not-ok markers and new non-test source lines mentioning `node:assert`, `node:test`, `syncBuiltinESMExports`, `process.exit`, `process.reallyExit`, `Module._load`, `require.cache`, `globalThis.process` fail as `harness_tamper` (`checks.harness_tamper: fail|warn`, default fail). (B2) per-file test counts (a reporter in the runner) for checks, protected and acceptance files; a file that runs fewer tests or becomes a file-only entry is `tests_reduced`, also in the task-level judge. (B3) **Tightening:** `checks.protect_existing_tests` is now ON by default (was off; goals can still turn it off, which is a listed loosening), and a modified test file or test helper that drops assertion calls fails as `tests_weakened` unless named exactly in `path_scope`. Goldens/tests that assumed the old default were updated deliberately (`reliability.test.mjs` protect test, one `anticheat.test.mjs` goal with an intentionally empty test file).
- Also: skipped+todo above the baseline run fails (`tests_skipped`) whatever the syntax; `package.json` `exports`/`type`, `.taprc`, `tsconfig*.json`, `jsconfig*.json` and `--import`/`--require`/`--loader`/`--env-file` targets in a check argv are test configuration (`check_config_changed`); plan approval warns when `acceptance_first` is on but no criterion has a check; the rules summary warns that `allow_loopback` is host-wide localhost on macOS; Node 18 fix: `node --test <glob>` is expanded by the engine (Node < 21 does not expand globs, so the baseline check failed and honest runs were blocked; the `tests_reduced` test failed on Node 18 CI); real Node 18 / 22 TAP fixtures in `test/fixtures`. `sandbox.mjs` gains a read-only `extraRead` dir for the preload. The CLI already honours `CLAUDE_PLUGIN_DATA` for the legacy state dir (now covered by a test).
- Installable: `package.json` `bin` (`npm link` gives an `aos-orch` command). `aos-orch --help` / `-h` print the full command list and exit 0; an unknown command exits 2.
- `run` now stays attached and waits for approvals by default (plan approval and `verify: "human"` criteria), applying your `approve-plan` / `confirm` without a second `run`; it exits only at achieved, blocked or cancelled. `--no-wait` restores the old exit-at-the-gate behaviour (exit 4 for a plan); **scripts and CI that call `run` and expect it to return at the gate must now pass `--no-wait`**; `--wait-approval` is now a no-op. `approve-plan` / `confirm` / `pause` ... from a second shell say "the attached run (pid N) will apply it within one tick" instead of "no engine is running" (the waiting run leaves `attached.json` in the goal dir).
- Default state dir is now `~/.aos/orch` (`$XDG_STATE_HOME/aos/orch`), independent of the dashboard plugin. If the old `~/.claude/plugins/data/aos-dashboard-aos-local/orch` exists and the new one does not, it is still used (one line on stderr). `AOS_ORCH_DIR` overrides both. The dashboard must read both locations.
- Worker crash visibility: the last 20 lines of a failed or crashed worker's stderr (control characters escaped) are stored in the `attempt_log` entry (`stderr_tail`), shown by `status` (`task_list[].last_stderr`) and in a "Worker errors" section of the report.
- The rules summary no longer prints an empty `LOOSENINGS YOU ARE APPROVING: none` block.
- Fix (budget cap race): a worker that had already delivered its result could be killed for the budget cap during its exit, discarding finished work and requeueing the task; budget kills now skip workers whose result is in, and a racing kill no longer discards a delivered result. The flaky cap test also assumed a 400 ms grace was enough for a loaded machine to start the fake worker; it now uses an ample grace.
- Docs: README rewritten around a three-command quickstart; the sandbox and policy prose moved to `docs/security.md` (SECURITY.md keeps the reporting policy and a short threat summary); new `docs/first-run.md` with two real runs.
- Anti-cheat layer (`lib/anticheat.mjs`): `node --test` checks run with the TAP reporter and are refused when they run 0 tests, only skipped/todo tests, or fewer tests than the base commit (`vacuous_pass`, `tests_reduced`; baselines recorded before the first dispatch); added skips in test files (`tests_skipped`, unless the plan task has `allow_skip`), changed test config / `package.json` scripts / scripts a check runs (`check_config_changed`, unless named in `path_scope`), deleted or renamed test files (`tests_deleted`). `checks.acceptance_first` (acceptance task writes tests first; read-only for other tasks; re-run at verify) and `checks.literal_copy: warn|fail` (hard-coded expected values). Results in `attempt_log[].anticheat`, `orch.anticheat.*` events, status, `report.md` and the advisory reviewer input.
- Demo UX: the draft display renders a criterion's lines separately instead of a literal `\u000a`; drafted goals get small default budgets (150000 tokens, 1200 s, 2 attempts, never above the rules) described truthfully (draft default / proposed by the model / your flag, with the rules' limit) and the rules summary shows the compiled limits; `aos-orch draft --max-tokens N --max-wall-s N --tier T` only tighten (validated before any model call). New read-only `aos-orch plan <goal>`; `run` prints the exact next command when it stops for plan approval or human confirmation; `run --wait-approval` stays attached and continues only after the human's `approve-plan` / `confirm` command. The rules summary lists a profile's own check-allowlist additions in a separate block from real loosenings. Plan review and the server plan view flag tasks whose `path_scope` is not mentioned in the goal text (`beyond_prompt`, `beyond_paths`; informational). The planner prompt discourages verification-only tasks. `rules check <goal.json> --layer goal` checks the goal file's `orch.rules`.
- Verification fixes: control, bidi and invisible characters are escaped in all worker-controlled text a human reads (control-server goal/approval/plan/event views, CLI `approvals`, `goals`, `status` JSON and text); the control-character set now also covers soft hyphen, U+034F, Hangul fillers, U+180E, U+2061-2064, U+206A-206F, interlinear annotation marks and lone surrogates. New plans bind the task title, description, output contract and acceptance into the tasks hash (`tasks_hash_v: 2`; plans approved earlier keep v1) and the plan review shows them. Glob complexity is bounded (variants x tokens <= 2048, `path_scope` <= 512 characters) and `scopeHitsDeny` has a work budget that answers "overlap" when exhausted.
- Prompt to goal (rules R12): `aos-orch draft "<prompt>" --repo <path>` and `POST /api/goals/draft` make one no-tools model call and return a validated draft (check argv only from the compiled check allowlist, budgets no higher than the rules, no rule or trust fields, control characters rejected, >= 2 criteria or a human-review one); nothing is created until the human submits. Vague prompts return questions. New criterion kind `verify: "human"`: the goal stays `blocked` ("awaiting human confirmation") until `aos-orch confirm <goal> <criterion>` or `POST /api/goals/:id/criteria/:cid/confirm`. `POST /api/goals` criteria may carry a `check` (it must already be allowed by the rules or the request's `check_allowlist`) or `verify`. Profiles `node-library` and `docs-only` for drafts.
- Rules R10: `aos-orch rules show [goal]`, `rules check <file> [--layer]` and `rules explain <goal> <task> '<tool json>'` (a pure dry run of the policy evaluate: decision, reason and rule id; writes nothing, creates no approval).
- Rules R9: `approval_policy.outside_allowlist: "deny"` now maps onto `worker.bash.ask_on` (unknown commands are denied, not asked); `approval_policy.dangerous`, unknown `approval_policy` keys, `policy.paths.write` and `policy.approval.on_timeout` are reported once in an `orch.rules.deprecated` event and otherwise ignored. Old goals still load.
- Rules R8: the retry ladder, `retry.same_tier_retries`, `retry.no_escalate`, `retry.uncertain_limit_max`, `budgets.soft_frac`, `budgets.hard_grace_s`, `parallel.soft_budget_blocks_tier`, `plan.planner_tier` and `plan.planner_timeout_s` now come from the compiled rules (defaults reproduce the old constants). The governor thresholds come from the user layer only (a goal's `orch.governor` is ignored; legacy goals keep it). Engine events `task.retried`, `task.failed` (final), `budget.exceeded`, `orch.governor.paused`, `orch.integrate.conflict` and `orch.plan.approval_required` carry `data.rule`.
- Opt-in macOS OS sandbox for worker `claude` processes: `aos-orch run goal.json --sandbox-workers` / `orch.sandbox_workers`. Limits writes (worktree, goal tmp, approvals, its own session-env and scratchpad); network and keychain reads stay open. Default unchanged. Guards against accidents; not a boundary against a determined malicious worker.
- Worker sandbox no longer allows writes to `~/.claude/shell-snapshots`, `~/.claude.json`, other sessions' `~/.claude/session-env/<id>` and `/tmp/claude-<uid>/` scratchpads, or the engine's `$TMPDIR`.
- Lock fix: `serve` no longer holds a goal's lock without ticking it; `run` against a locked goal exits 5; `lockStatus` treats a lock older than its ttl as dead (no WEDGED message naming a reused pid).
- Rate-limit matcher keyed on real captured error shapes; text fallback now applies only to API-error-shaped results (never worker-authored result text or `errors[]`); after 2 consecutive uncertain matches for a task the attempt counts; a real limit during a shorter overload pause extends the pause (longer wins); a manual pause is never replaced by a timed one.
